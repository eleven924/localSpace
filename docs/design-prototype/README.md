# LocalSpace 视觉方向原型

这是一个独立的静态设计原型，不接入 Wails，也不修改现有 `frontend/src` 产品源码。直接打开 `index.html` 即可查看；如果浏览器限制本地文件脚本，也可以在本目录启动任意静态服务器。

## 现状判断

当前产品的功能结构是清楚的：文件、合集、导入、任务、设置、说明各自有入口，文件页也已经具备类型筛选、合集筛选、搜索、平铺/分组和分页等必要能力。

目前影响“精美感”的主要不是功能少，而是信息层级没有拉开：

- 文件页把类型、合集、批量操作、搜索、结果摘要和视图切换堆进同一个大工具面板，筛选区在首屏形成了第二个“页面主体”。
- 大量控件都是相同的圆角胶囊和浅灰边框，交互优先级不够明显，品牌记忆点偏弱。
- 页面之间虽然复用了颜色变量，但缺少一致的空间骨架；文件页偏工具面板，导入/设置/说明页又偏内容卡片，像几个独立模块拼在一起。
- 文件卡片的信息密度基本合理，但缩略图、文件类型、描述、标签和更新时间的视觉关系还可以更明确。

## 这轮确定的方向

原型采用“Quiet Archive / 静谧资料工作台”作为整体风格：

- 结构：左侧常驻导航承载产品结构；内容区只承载当前任务；顶部只保留路径、全局操作和用户状态。
- 材质：雾面浅灰蓝画布、半透明白色纸面、极轻阴影和细边线，避免所有区域都变成漂浮白卡。
- 颜色：深墨蓝文字 `#152238`、雾面画布 `#eef2f7`、行动蓝 `#2678da`，辅以克制的薄荷、琥珀、玫瑰和紫色状态色。
- 字体：系统 UI 字体负责可读性，Avenir / SF Pro Display 负责标题的轻微品牌感，等价 fallback 不依赖网络字体。
- 记忆点：把文件类型色片与真实的文件缩略图区域组合起来；分页仍位于右下角，但作为低存在感的玻璃悬浮控制。

## 筛选区怎么改

文件页首屏只显示“搜索 + 筛选 + 视图切换”一行工具带。类型和合集不再默认展开；点击“筛选”后，在按钮附近出现小型浮层，用户选中后只留下轻量 active filter chip。这样筛选能力仍在，但不会压过文件内容。

原型里还保留了按合集分组的切换、分页、导入模式切换、任务状态和设置分组等关键路径，便于比较整套产品的统一性。

## 第二轮收敛

源码自评后做了三处调整：顶部工具栏加入轻微雾面层，让它与左侧导航和内容画布属于同一材质；筛选浮层从 430px 收到 390px，并降低阴影对比，避免“点击筛选”后又出现一个新的大面板；合集页的统计信息改为靠右对齐，让标题、动作和数量形成清晰的三段节奏。

## 第三轮反馈修正

- 移除了顶栏没有明确去向的搜索图标。正式产品的搜索范围是资料库内的文件名、标签和描述，应继续放在文件页工具带里；如果未来做全局搜索，需要单独定义跨页面结果面板，不与文件页搜索混用。
- 补回右上角任务状态入口，用进行中的环形状态标识和小型任务浮层承接 `GetActiveJobs` / `ListJobs` 的信息。
- 设置原型现在明确区分“已有接口”和“需要新增接口”：存储目录、存储规则、打开方式、主题、AI、任务保留属于现有能力；启动恢复、自动缩略图策略、布局和分页持久化属于后续偏好设计。

## 第四轮反馈修正

- 设置内导航与右侧设置内容使用同一条顶部对齐线，并在页面滚动时保持 sticky，避免切换到设置后左侧导航像被内容推着下沉。
- 全局左侧导航增加收起按钮；收起后保留图标和状态，不隐藏产品结构，也不挤压当前工作区。
- 通知占位图标改为标准铃铛 SVG，避免花朵符号带来错误语义。

## 第五轮反馈修正

补充“任务进行中时退出应用”的保护流程。原型增加了一个关闭应用触发器：当存在 `pending / running / recovering` 任务时，先展示受保护任务数量、当前进度、是否可恢复，以及“返回应用 / 查看任务 / 仍然退出”三个明确动作。它对应现有的 `GetExitGuardSnapshot` 与 `ConfirmQuit` 能力，原型中的“仍然退出”只显示提示，不会真的关闭浏览器窗口。

## 第六轮反馈修正

- 移除本地客户端没有实际意义的用户头像，不预留登录语义。
- 将全局侧栏收起动作放进底部设置区，单独占一行，不再挤占 LocalSpace 品牌行。
- 资料库、合集、导入、任务、设置统一使用紧凑页头；使用说明作为内容型页面保留大标题，形成“工作页快速进入内容、说明页允许阅读”的层级差异。（导入页在第九轮改用标签页头，见下。）

## 第七轮：导入页重做

导入只能通过系统文件窗口选文件，不支持拖拽，所以这一轮把导入页按这个前提重排。

- 删除虚线拖放区。虚线框和「拖入文件」是拖拽的通用信号，页面不支持拖拽时它就是一句假话。取而代之的是一个实线、实心、带文件夹图标和右箭头的选择控件，读起来是按钮而不是投放目标。副标题直接说明操作方式：单文件「一次选择一个文件」，批量「按住 Ctrl / Shift 可一次选多个」。
- 删除 1 / 2 / 3 步骤条。它装饰的是一个本来就只有两步的流程，而且真实的完成状态由「有没有选中文件」决定，不由步骤条决定。
- 两种模式用不同骨架，因为内容本身不同：单文件只有一个主体，于是它是横跨整宽的来源条（选择控件 + 已选文件），下面才是元信息和 AI 分析两栏；批量是一份清单，于是它占满左栏，右栏放公共字段。之前两种模式共用左右分栏，单文件模式下左栏只有一个文件卡，右侧留下大片空白。
- 文件类型色片作为记忆点从资料库延续到导入：影 / 文 / 音 / 图 / 压 / 装 各有一块低饱和底色，和文件卡片用的是同一套类型语言。批量列表因此有了可扫的节奏。
- 提交动作从面板内部移到工作区底部右侧，两种模式位置一致，让「立即导入文件 / 创建后台导入任务」始终是页面的最后一步。
- 页头保持紧凑，模式切换放在标题行右侧；切换时只换下方工作区和一句说明，页头不跳动。

功能和接口没有变化：单文件仍走 `SelectFile` → `ParseFileType` → `GetMetadata` → 提交单文件导入任务，批量仍走 `SelectFiles` → 去重追加 → `SubmitBatchImportJob`，AI 建议仍对应 `FileMetadataFields` 里的分析、应用描述和应用全部。

## 第八轮：把「不正常」的状态补齐

第七轮只画了「已经选好文件、字段都合法」这一个画面，但 `ImportView.vue` 里有 42 处 `singleError` / `batchSuccess` / `Submitting` / `CanSubmit` 状态没有对应设计，空状态又恰恰是每个用户第一眼看到的东西。这一轮补上：

- **空状态**。单文件未选中时，来源条右半边变成「还没有选择文件」，元信息收成一条 132px 的提示带，AI 栏整个不渲染，布局收成一栏。批量清空后统计块一起隐藏——「预计体量 0 B」不提供任何信息。
- **结果反馈**。提交结果放在底部动作行的左端，成功用薄荷底、失败用玫瑰底，和动作在同一行，不额外占一层。对应 `singleError` / `singleSuccess` / `batchError` / `batchSuccess`。
- **禁用与提交中**。没有文件时主按钮禁用（对应 `singleCanSubmit` / `batchCanSubmit`）；提交期间按钮变成「正在导入... / 正在创建任务...」并锁住，对应 `singleSubmitting` / `batchSubmitting`。
- **AI 未配置时的布局**。上一轮 README 写了「元信息占满整行」，但 `.single` 固定是 `1.3fr / .7fr`，AI 栏不渲染时右边会空掉 35%——文档和实现对不上。补了 `.single.solo` 单栏模式，未选文件和未配置 AI 共用它。
- 顺手删掉重构留下的死 CSS（`.imp-actions`、`.imp-locked-mark`），并给两个工作区补上 `role="tabpanel"` 和 `aria-labelledby`。

这些状态都由**真实动作**驱动，没有加原型专用的状态切换器：点「移除」进空状态，点「清空列表」清空批量清单，点单行「移除」会按剩余文件重算数量和体量，点主按钮会走一遍「提交中 → 成功 → 回到空状态」。评审时顺着这些路径点一遍就能看全。

## 第九轮：去掉页面大标题，让模式切换充当页头

左侧导航高亮、面包屑、页面大标题三处都在写「导入」，标题是纯冗余。但直接删掉标题会留下一个问题：模式切换原来挂在标题行右端，标题没了之后它就成了一个悬空的小部件，切换时很突兀。

处理方式是**让模式切换本身成为页头**——它切换的是整个工作区，本来就是这一页的主控件，不是某个次要选项：

- 胶囊式分段控件换成下划线标签栏，移到左上原标题的位置。标签栏底部那条通栏细线接管了大标题原有的视觉重量，页面顶部重新有了锚点。
- 标签字号定在 17px。第一版试过 14px，结果比面板标题（15px）还小，页面级控件反而排在它内部的分区下面，层级是倒的。
- 说明文字降为 11px 灰字，放在线下方。批量那句要保留，因为它是唯一说明「会创建后台任务」的地方。
- 页面标题改为 `visually-hidden` 的 `h1`，屏幕阅读器和文档大纲仍然拿得到「导入」，只是不占视觉空间。
- 导入页因此不再使用 `compact-page`（那套规则只作用于 `.page-heading`），它现在是全站唯一用标签页头的工作页——因为它也是唯一一个「模式切换整个工作区」的页面。其余页面继续用紧凑标题页头。

## 第十轮：任务页重做

任务页原来是一张 6 列表格（任务 / 开始 / 结束 / 进度 / 状态 / 操作），窄屏还要靠一整套 `table → 卡片` 的降级规则。这一轮按内容本身重排。

**状态是主要扫描轴，所以它移到行首。** 用户来这一页是为了回答「有没有卡住或失败的」，但状态原来是第 5 列的一个胶囊，被埋在中间。现在每行左侧有一条 3px 色条，扫一眼就知道有没有异常。

**颜色只标记需要你处理的东西。** 这是这一页最关键的取舍：进行中是电光蓝（当前状态），等待继续是琥珀，失败是玫瑰，**已完成不着色**。如果每条完成记录都是绿色，历史列表会变成一片绿，真正的异常反而看不见了。安静的资料库不需要为每个完成的任务庆祝。

**进度条只在还在跑的时候出现。** 终态显示结果本身更有信息量——「成功 38 个 · 失败 2 个」「已清理 12 条记录」比一根 100% 的灰条有用。

**类型筛选沿用资料库的工具带。** 「筛选」按钮 + 小型浮层 + active chip，和文件页是同一套交互，不再让用户学第二种筛选方式。用 `ListJobs` 已有但一直传 `''` 的 `jobType` 参数，四个选项各带一个数量。原来顶部那两张统计卡片（活动任务 / 总记录）收成工具带右侧的一行文字——两个数字是两条事实，不值得做成两张卡片。

需要说明一个边界：`ListJobs` **只支持按 jobType 过滤，不支持按状态过滤**，所以浮层里只有「任务类型」一组。如果以后想按「进行中 / 失败」筛，得先给后端加参数，否则只能在当前页做前端过滤，会和分页打架。

**空列表的出路取决于它为什么空。** 被筛没的显示「没有清理任务」+「清除筛选」；真的没有记录才显示「还没有任务记录」+「前往导入」。给一个空页面配一个走不通的动作，比不给动作更让人困惑。

**补上取消入口。** 后端有 `CancelJob`、store 有 `cancelJob`，但界面上没有任何入口，进行中的任务无法停止。原型里给 `pending / running / recovering` 加了「取消」。

**详情是行的延伸，不是浮层。** 展开后贴着行底边内嵌一块浅色区，分三列显示错误信息、执行结果和任务 ID，符合「纸面卡片只承载真实内容」。

两处实现细节值得记：

1. 每一行都是独立的 grid，操作列如果用 `auto`，按钮数量不同的行（1 个「取消」vs 2 个「详情 + 删除」）会把 `1fr` 挤成不同宽度，导致时间、进度、状态三列在行与行之间错位，纵向就扫不成列了。操作列必须定宽。
2. 这个原型里已经三次踩到同一个坑：元素自带 `display: grid / flex / inline-flex` 时，`hidden` 属性会失效。之前是逐个补 `.x[hidden] { display: none }`，这轮改成一条全局 `[hidden] { display: none !important; }`，并删掉了四处零散的补丁。

窄屏不再走表格降级：行收成三层——标题、进度、状态与操作同处一行。

## 第十一轮：设置页重做

之前的设置原型不是一个设置页，是一份接口盘点文档：两张卡片列着「已有明确接口」和「需要新增偏好」，下面还压着一段 `display: none` 的旧版布局，里面「启动时打开资料库」「每页显示 50 份」这些开关在 `SettingsView.vue` 里根本不存在。这一轮按真实的 8 个分区重做。

**导航不包白卡。** 设置页自己需要一条分区导航，但如果按之前那样把它做成一张圆角白卡，它就会和左侧全局导航变成两张并排的纸——违背「纸面卡片只承载真实内容」。改用说明页那套「页内目录」的写法：画布上的列表、左侧一条电光蓝色条标记当前项、分组名做小号字标签。全站因此只有一种页内导航语言。5 个分组（通用配置 / 主题 / AI 配置 / 专项配置 / 关于）保留为标签，它们说明了存储目录、存储规则、打开方式属于同一族，这条信息值 8 个字。

**页面标题换成当前分区。** 左导航高亮、面包屑、页面大标题三处都在写「设置」，和导入页第九轮遇到的是同一个冗余。但设置页的分区切换在左侧，不能像导入页那样让切换器充当页头。所以让**当前分区**成为页头：进到存储目录时，这一页的主题就是存储目录，不是「设置」。副标题直接用 `settingItems` 里那批 `context` 字段——它们在源码里定义了，但从来没有渲染过。头部下方那条通栏细线接管页面顶部的重量，和导入页标签栏底部的线是同一个装置。

**把保存模型的不一致写出来。** 这一页有三种保存方式：主题每改一次就直接落库（没有保存按钮）、存储目录和合集每个动作立即生效、存储规则 / 打开方式 / AI / 任务是显式保存的表单。前两种没有保存按钮不是漏了，是设计如此，所以在页头右侧放一枚「改动立即生效 / 修改后立即生效」的灰标。缺一个按钮会让人找，写一句话就不会。

**底部动作行直接沿用导入页。** 反馈在左端、动作在右端，成功用薄荷、失败用玫瑰。源码里现在有四套反馈机制（`alert` / `.message` / `.test-result` / 2600ms 自动消失的 `.action-message`），原型把它们统一到这一条，文案一字不改。

**内容列收到 880px。** 第一版让内容占满 975px，结果「存储结构」和它的下拉框分别贴在两端，中间空了 700px，一行设置要扫两次。880px 之后说明和控件回到同一次扫视里，通栏细线也不再横跨半个屏幕。

**文件类型色片第三次出现。** 影 / 文 / 音 / 图 / 压 / 装 从资料库到导入页，这一轮进到「打开方式」的七个类型行和「存储目录」的子目录列表——这两处本来就是按文件类型组织的。它是这套产品的连接组织，不是装饰。同一张主目录卡片里原来还有一枚只写着「目录」的色片，它和类型色片是两套语言，而且一行带反斜杠的路径本来就看得出是目录，删掉了。

**删除主目录值得一个真正的对话框。** 这是整页风险最高的动作——它会清空目录下的所有文件内容——现在却是一句 `confirm()`。原型给它一个玫瑰色顶边的 `alertdialog`：先复述要删的路径，再说明后果，确认键是描边的危险色而不是蓝色主按钮，避免「一路点蓝色」把资料删掉。添加主目录仍是普通对话框，蓝色主按钮。

状态一样由真实动作驱动：删完两个主目录会进「暂无主目录」；新添加的目录会真的插进列表，展开后是「暂无子目录」；关掉 AI 总开关下面所有字段会收起来，只留一句说明和保存按钮；改一下存储规则，路径预览会跟着变，保存会走「保存中 → 存储规则已保存」。

功能和接口没有变化。八个分区分别对应 `GetMasterDirectories` / `AddMasterDirectory` / `SetDefaultMasterDirectory` / `RemoveStorageDirectory` / `CheckPathConflict`、`Get/UpdateStorageLayoutConfig`、`Get/UpdateOpenWithConfig`、`Get/UpdateThemeConfig`、`Get/UpdateAIConfig`、`GetAllCollections` / `AddCollection` / `RemoveCollection`、`Get/UpdateJobRetentionConfig` / `SubmitCleanupJob`，以及只跳文档、不发请求的「关于」。

两个需要留给实现的边界：

1. **AI 的「测试连接」目前是假的**。`AIConfigForm.vue` 里它 `setTimeout` 1500ms 然后无条件返回成功，真正的 `TestAIConnection` 调用被注释掉了。原型照着现状画（转圈 → 成功），但它在正式版里应该接后端，否则这个按钮只是在骗人。
2. **合集的「引用 N」在真实页面上恒为 0**。`CollectionsSettings` 的计数来自 `filesStore.files`，而 `SettingsView` 从不调用 `loadFiles()`。直接进设置页时计数全是 0，于是「被引用的合集不能删除」这条保护完全失效。原型按计数正常工作来画，实现时需要在设置页补一次加载，或者把计数改成后端返回。

## 第十二轮：把设置页落到产品代码

原型定稿后按「接口是事实标准、原型是目标样式」把设置页搬进 `frontend/src`。接口调用一个没动（20 个原有调用全部保留），改的是版式。

**共用装置抽成一张表。** 八个分区分散在七个子组件里，如果每个组件各写一套 scoped 样式，同一条设置行会有七种间距。设置行、控件、色片、对话框集中放进 `frontend/src/assets/styles/settings.css`，由 `SettingsView` 用 `<style src>` 引入，全部以 `set-` 前缀命名。这也让 `SettingsView` 里那 200 多行 `:deep()` 归一化 CSS 可以整段删掉——那些规则是在替子组件补衣服，现在子组件自己穿对了。

**颜色不写死。** 原型里是固定的静谧色值，产品这一页得同时活在浅色和深色下，而且「主题」分区本身就在改强调色。所以 `--set-accent` 直接跟随 `--primary-color`：选完颜色，左侧导航的选中态当场变过来，否则这一页在骗人。类型色片沿用导入页已有的浅色/深色两套值。

**文件类型短标签只留一处。** 影 / 文 / 音 / 图 / 压 / 装 原来写死在 `ImportView.vue` 里，设置页要用第二次，于是提到 `utils/constants.ts` 的 `FILE_TYPE_META`，导入页改为引用。

顺带修掉三处实现问题：

1. **合集的「引用 N」恒为 0**（原型第十一轮记的边界）。计数原来来自 `filesStore.files`，而设置页从不加载文件列表，于是「被引用的合集不能删除」这条保护完全失效。现在改调后端已有的 `GetCollectionFilterCounts`，一次请求拿到全量计数，不受列表分页影响。
2. **主目录卡片把「已用」和「上限」当成一回事**：`formatSize(0)` 一律返回「未限制」，一个空目录会显示成「未限制 / 未限制」。已用为 0 只是还没放东西，上限为 0 才是未限制。
3. **对话框被侧栏盖住**。侧栏是 `z-index: 80` 的固定层，新对话框写了 60，遮罩铺满了但侧栏浮在上面。改成和站内其他弹层同级的 1000。

反馈机制按原型统一：`alert()` / `confirm()` 退出设置页，结果写在底部动作行或清单下方那一行。只保留两个真正设计过的确认——删除主目录（会清空目录内容）和重置主题（会丢掉背景图片，这一分区里唯一找不回来的东西）。AI 的测试结果和保存结果拆成两条：一条贴着测试按钮，一条在底部动作行，它们原来共用一个变量，保存成功的提示会跑到测试按钮旁边。

需要留意的工具链问题：`npm run build` 只跑 `vite build`，**不做类型检查**，而 `vue-tsc` 在当前 TypeScript / Node 版本组合下直接抛错跑不起来。这轮就有一个「引用了已删除的 import」的错误通过了构建，只在浏览器里白屏才暴露出来。改完设置页这类多文件改动，建议在浏览器里逐个分区点一遍，别只看构建结果。

## 本轮自评与下一步

第一轮完成后，原型已经有更明确的骨架，但仍然需要真实业务数据和不同窗口尺寸下的对照截图才能继续精确微调。当前优先级建议是：

1. 先验证文件页的首屏比例和筛选浮层是否足够安静。
2. 再用真实缩略图替换原型渐变占位，检查图片、视频、文档混排时的节奏。
3. 最后再决定深色主题是否沿用同一套材质，避免为了“有主题”而引入另一套视觉语言。
