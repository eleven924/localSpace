# 文件展示中的标签悬浮与元信息编辑设计

## 背景

当前文件列表卡片已经支持：

- 展示前 3 个标签，超出部分显示 `+n`
- 通过右上角三点菜单执行文件详情、打开文件夹、重命名、删除
- 在导入流程中编辑标签和描述，并通过 AI 生成建议标签和描述

本次需求是在现有体验上补齐两个关键能力：

1. 当标签超过 3 个时，鼠标悬停在 `+n` 上可查看剩余标签
2. 在文件卡片右上角三点菜单中增加“编辑标签和描述”，支持手动修改与 AI 辅助处理

## 目标

### 用户目标

- 在不进入详情页的情况下，快速查看文件的完整标签集合
- 在文件列表页直接修改标签和描述，减少跳转与重复操作
- 在编辑标签和描述时继续复用已有 AI 能力，提高整理效率

### 产品目标

- 保持文件列表页的轻量浏览体验
- 保持与现有导入编辑体验的一致性
- 以尽量小的改动范围实现可维护的结构扩展

## 非目标

本次不包含以下范围：

- 不新增文件名编辑能力到该弹窗中（文件名继续通过“重命名”处理）
- 不改造移动端专属的标签展开交互，仅保留桌面端 hover 行为
- 不重做整个导入页结构
- 不修改文件详情弹窗的信息结构

## 方案概述

采用“最小改动复用现有能力”的方案：

- 为文件卡片中的 `+n` 增加轻量 tooltip，用于展示隐藏标签
- 在三点菜单中新增“编辑标签和描述”入口
- 新增独立的编辑弹窗组件，用于编辑 tags / description
- 复用现有导入表单中的标签、描述、AI 建议交互能力，避免重复实现
- 增加更新文件元信息的前后端接口
- 保存成功后，按当前列表上下文刷新文件列表

## 交互设计

### 1. 标签 `+n` 悬浮查看

#### 当前行为

- 文件卡片仅显示前 3 个标签
- 超过 3 个时显示 `+n`

#### 新行为

- 继续默认显示前 3 个标签
- 当标签数量大于 3 时，显示 `+n`
- 鼠标悬停在 `+n` 上时，展示一个轻量 tooltip
- tooltip 中只显示隐藏的剩余标签，不重复前 3 个标签
- tooltip 内的标签继续使用 tag 样式展示，以保持视觉一致性
- 如果剩余标签较多，tooltip 允许自动换行，不应撑破文件卡片布局

#### 交互原则

- tooltip 仅作为补充查看方式，不改变卡片原有布局高度
- 对于标签数小于等于 3 的文件，不显示 `+n`，也不显示 tooltip
- 对于移动端，无需额外新增点击展开交互，保持当前静态表现

### 2. 三点菜单新增编辑入口

#### 菜单结构

在现有文件卡片三点菜单中新增：

- 文件详情
- 打开文件夹
- 重命名
- 编辑标签和描述
- 删除文件

#### 排序原则

- 编辑标签和描述属于常规编辑操作，应放在删除之前
- 删除保持在最底部，维持危险操作隔离

### 3. 编辑标签和描述弹窗

#### 打开方式

- 用户点击三点菜单中的“编辑标签和描述”后打开弹窗

#### 弹窗内容

弹窗标题：`编辑文件信息`

弹窗中包含：

- 当前文件名展示（只读，用于上下文确认）
- 标签输入框
- 标签预览与移除能力
- 描述输入框
- AI 分析区域
- 底部操作按钮：取消 / 保存

#### 初始化规则

- 标签输入框默认带入当前文件已有 tags
- 描述输入框默认带入当前文件已有 description
- AI 不自动运行，作为补充建议能力由用户主动触发

#### AI 行为

保留与导入流程一致的 AI 交互：

- 支持点击生成 / 重新生成
- 支持查看 AI 建议标签
- 点击建议标签可追加到当前标签中
- 支持单独应用 AI 描述
- 支持一键应用全部 AI 建议
- AI 生成失败时不影响用户手动编辑

#### 保存结果

保存成功后：

- 关闭弹窗
- 刷新当前文件列表
- 卡片上的标签和描述应即时更新

## 组件设计

### 1. `frontend/src/components/FileCard.vue`

职责：

- 展示文件卡片
- 展示 `+n` 及其 tooltip
- 提供三点菜单入口
- 打开/关闭编辑文件信息弹窗
- 在编辑成功后向父组件发出刷新事件

不承担：

- 不内嵌完整元信息编辑表单逻辑
- 不直接承载复杂 AI 编辑流程

### 2. 新增 `frontend/src/components/EditFileMetaModal.vue`

职责：

- 接收当前 file 数据
- 初始化 tags / description
- 提供 AI 分析与应用能力
- 调用保存接口
- 成功后发出 `updated` 事件

该组件作为文件列表场景下的专用编辑弹窗，与 `FileCard.vue` 保持清晰分层。

### 3. 复用元信息编辑逻辑

当前 `frontend/src/components/FileMetaForm.vue` 同时承担：

- 文件导入专属流程（文件名、导入提交、导入进度）
- 通用元信息编辑能力（标签、描述、AI 建议）

本次设计要求将“通用元信息编辑能力”做小范围复用，以服务：

- 导入流程中的 `FileMetaForm.vue`
- 文件列表中的 `EditFileMetaModal.vue`

推荐做法：

- 抽出标签、描述、AI 区域为一个可复用子组件，或
- 抽出对应 composable / 逻辑层

要求：

- 不复制整套 AI 与标签处理逻辑
- 不为这次需求做过度重构
- 保持导入流程当前行为不变

## 数据流设计

### 用户编辑流程

1. 用户在文件卡片点击三点菜单
2. 点击“编辑标签和描述”
3. 打开编辑弹窗，并带入当前 tags / description
4. 用户手动修改内容，或触发 AI 生成建议
5. 用户点击保存
6. 前端调用更新文件元信息接口
7. 保存成功后关闭弹窗
8. `FileCard` 向上层发出刷新事件
9. 父层根据当前上下文刷新文件列表

### 刷新规则

保存成功后的刷新必须保持上下文一致：

- 如果当前处于搜索结果页，刷新后应继续使用当前搜索条件
- 如果当前处于某个文件类型筛选条件下，刷新后应继续停留在该筛选条件
- 不应因为一次编辑而回退到全量文件列表

## API 与后端设计

### 前端 API 层

当前前端已有：

- `rename`
- `delete`
- `open`
- `openLocation`
- `refresh`
- `ai.analyze`

本次新增：

- `api.file.updateMetadata(id, tags, description)`

要求：

- 该接口属于写操作，失败时应显式抛错
- 不应使用 silent fallback 吞掉异常
- 调用方应能根据失败状态保留用户输入并提示重试

### Wails / 后端接口

需要新增对应后端能力，例如：

- `UpdateFileMetadata(id, tags, description)`

后端职责：

- 根据文件 ID 更新数据库中的标签和描述
- 做必要的输入规范化处理
- 返回成功结果，或在失败时返回错误

### 数据规范

- tags 允许为空数组
- description 允许为空字符串
- 标签继续沿用现有前端去重逻辑
- 标签内容在保存前应去除首尾空格

## 错误处理

### AI 生成失败

- 不关闭弹窗
- 不清空用户当前输入
- 用户仍可继续手动编辑
- 至少记录错误日志；如项目已有统一提示方式，则展示用户可见提示

### 保存失败

- 弹窗保持打开
- 保留当前标签与描述输入内容
- 提示用户“保存失败，请重试”

### Wails 不可用或接口异常

- 对写操作使用直接 reject/throw 的调用方式
- 不使用默认成功值掩盖失败
- 调用栈中由弹窗组件进行可见提示和状态恢复

## 状态与边界条件

### 标签相关

- 0 个标签：不展示标签区块
- 1~3 个标签：直接全部展示，不显示 `+n`
- 大于 3 个标签：显示前 3 个 + `+n`
- tooltip 仅展示第 4 个及之后的标签

### 描述相关

- 描述为空时允许保存
- 文件卡片中若描述为空，则不展示描述段落

### 编辑相关

- 弹窗打开时必须回填当前已有数据，而不是空白表单
- AI 建议标签追加时应去重
- 一键应用全部时同时应用 AI 描述和 AI 标签

## 测试设计

### 交互验证

- `+n` 在 hover 时显示剩余标签
- tooltip 只显示隐藏标签，不重复前 3 个
- 标签很多时 tooltip 可换行展示
- 菜单中出现“编辑标签和描述”项

### 表单验证

- 弹窗打开时正确带入当前 tags / description
- 用户可手动删除、追加、修改标签
- 用户可手动编辑描述
- 标签为空、描述为空时可以保存

### AI 验证

- AI 可成功生成建议标签和描述
- 建议标签可点击追加
- AI 描述可单独应用
- 一键应用全部可用
- AI 失败时不影响手动编辑

### 保存与刷新验证

- 保存成功后弹窗关闭
- 保存成功后文件卡片内容即时更新
- 在筛选状态下保存后仍停留在当前筛选结果
- 在搜索状态下保存后仍停留在当前搜索结果
- 保存失败时表单内容不丢失

## 实施建议

推荐按以下顺序实施：

1. 新增后端更新文件元信息接口
2. 在前端 `api.file` 中新增 `updateMetadata`
3. 抽出可复用的标签/描述/AI 编辑逻辑
4. 新增 `EditFileMetaModal.vue`
5. 在 `FileCard.vue` 中接入菜单项与弹窗
6. 为 `+n` 增加 tooltip
7. 接通刷新事件并验证筛选/搜索上下文

## 风险与控制

### 风险 1：复用导入表单时耦合过深

控制方式：

- 仅抽离标签、描述、AI 相关区块
- 导入行为与导入进度保留在现有导入组件中

### 风险 2：保存后刷新打断当前上下文

控制方式：

- 刷新事件统一走当前 `FilesView` 的既有搜索/筛选逻辑
- 不直接写死为 `loadFiles('all')`

### 风险 3：`FileCard.vue` 继续膨胀

控制方式：

- 编辑表单放入独立 modal 组件
- `FileCard.vue` 只保留入口、状态和事件转发

## 最终结论

本次功能应以局部增强的方式落地：

- 用轻量 tooltip 补齐 `+n` 的剩余标签可见性
- 用独立弹窗补齐文件列表内的标签与描述编辑能力
- 复用现有 AI 元信息生成逻辑
- 增加正式的元信息更新接口
- 确保保存后在当前搜索/筛选上下文内刷新

该方案能够在最小范围内提升文件整理效率，同时避免重复实现已有 AI 与元信息编辑能力。
