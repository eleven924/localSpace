# LocalSpace 页面设计实施方案

> 目标：在不偏离现有产品事实、接口和任务状态模型的前提下，完成 LocalSpace 统一页面视觉升级。
>
> 原则：严格依赖实现，严格依赖设计；产品事实是第一标准，独立 HTML 原型只作为视觉探索和交互参考。

## 1. 总体实施原则

本次工作不从“原型长什么样”开始，而从“产品现在真实能做什么”开始。

```mermaid
flowchart LR
  A[产品事实与真实接口] --> B[前端状态模型]
  B --> C[共享应用壳层]
  C --> D[各页面设计落地]
  D --> E[原型对照与验收]
  A -. 约束 .-> E
```

每一个设计元素都必须能够回答以下问题：

1. 数据从哪个真实接口或前端状态来？
2. 加载、空状态、错误、无权限或未初始化时如何显示？
3. 用户点击后会触发什么现有行为？
4. 如果当前没有接口，是暂不展示，还是先补接口后展示？

原型可以表达未来方向，但不能把示例数据、装饰性状态或假想能力直接复制进正式产品。

## 2. 已确认的产品事实

### 2.1 路由与页面

当前正式页面由以下路由组成：

- `/files`：文件资料库。
- `/collections`：合集浏览。
- `/import`：单文件导入和批量导入。
- `/tasks`：任务列表、状态和历史记录。
- `/settings`：存储目录、存储规则、打开方式、主题、AI、合集、任务保留、关于。
- `/documentation`：使用说明。

事实来源：[frontend/src/router/index.ts](../frontend/src/router/index.ts)。

### 2.2 文件页事实

- 文件列表通过 `GetFiles(page, pageSize, fileType, collectionId)` 获取。
- 文件搜索通过 `SearchFiles(query, page, pageSize)` 获取，搜索范围应继续表达为文件名、标签、描述等资料库内容。
- 类型筛选、合集筛选、搜索、平铺 / 按合集分组和分页已经存在前端状态与路由同步逻辑。
- `pageSize` 当前默认值为 50，`listMode` 当前由文件页和路由状态维护。

事实来源：[frontend/src/views/FilesView.vue](../frontend/src/views/FilesView.vue)、[frontend/src/store/modules/files.ts](../frontend/src/store/modules/files.ts)、[frontend/src/api/index.ts](../frontend/src/api/index.ts)。

设计约束：不新增一个没有结果定义的“全局搜索”；搜索入口只放在文件页工具带中。若未来需要跨页面搜索，必须先定义搜索范围、结果模型、路由和空状态。

### 2.3 任务与退出保护事实

- 任务状态来自 `GetActiveJobs()`、`ListJobs(...)` 以及 Wails 任务事件。
- 任务状态入口已经存在于正式 `AppHeader` 的 `TaskStatusIndicator` 中。
- 退出保护接口为 `GetExitGuardSnapshot()` 和 `ConfirmQuit()`。
- 只有 `pending`、`running`、`recovering` 任务会进入退出保护；任务快照还包含进度、状态和 `canResume`。
- 正式产品已经通过 `ExitGuardDialog` 展示“返回应用、查看任务、仍然退出”。

事实来源：[frontend/src/components/TaskStatusIndicator.vue](../frontend/src/components/TaskStatusIndicator.vue)、[frontend/src/components/ExitGuardDialog.vue](../frontend/src/components/ExitGuardDialog.vue)、[frontend/src/store/modules/jobs.ts](../frontend/src/store/modules/jobs.ts)、[frontend/src/store/modules/exitGuard.ts](../frontend/src/store/modules/exitGuard.ts)、[app/app.go](../app/app.go)。

设计约束：任务状态必须是共享壳层的一等信息；退出保护不能设计成普通的“确定退出”弹窗，必须保留受影响任务、可恢复性和三个现有动作。

### 2.4 设置事实

当前已经存在明确配置接口和设置组件：

| 设置能力 | 当前事实 | 实施方式 |
|---|---|---|
| 存储目录 | 有主目录、默认目录和目录操作接口 | 直接复用 `StorageDirSelector` 和 storage API |
| 存储规则 | 有 `Get/UpdateStorageLayoutConfig` | 直接复用 `StorageLayoutConfig` |
| 打开方式 | 有 `Get/UpdateOpenWithConfig` | 直接复用 `OpenWithConfig` |
| 主题 | 有 `Get/UpdateThemeConfig`，主题启动时初始化 | 直接复用 `ThemeConfig` 和 theme store |
| AI | 有 `Get/UpdateAIConfig` | 直接复用 `AIConfigForm` |
| 合集 | 有合集读写接口 | 复用 `CollectionsSettings` |
| 任务保留 | 有 `Get/UpdateJobRetentionConfig` | 复用 `TaskRetentionSettings` |
| 关于 / 说明 | 当前是前端展示和路由行为 | 保持事实文案，不伪造在线服务 |

事实来源：[frontend/src/views/SettingsView.vue](../frontend/src/views/SettingsView.vue)、[frontend/src/api/index.ts](../frontend/src/api/index.ts)。

以下内容当前不能直接作为正式设置项：

- 启动时恢复上次页面或筛选状态。
- 导入后自动生成缩略图的策略开关。
- 默认布局持久化。
- 每页数量跨重启持久化。

缩略图生成和缓存接口本身已经存在，但“自动生成策略”没有独立配置事实。以上项目如果要实现，必须先补充配置键、默认值、读取时机、保存接口和迁移策略，再进入正式设置页。

### 2.5 不应出现在正式产品里的原型内容

- 用户头像或登录状态：LocalSpace 当前是本地客户端，没有登录体系。
- 顶栏全局搜索：当前没有明确的跨页面搜索能力。
- “本地资料库 · 正常”：当前没有对应的统一健康状态接口，不能用装饰性绿点代替真实数据。
- 虚构的文件数量、任务数量、同步时间和健康状态：正式页面必须使用真实接口返回值、加载态、空态或错误态。
- 未接线的偏好开关：不能因为原型里有开关，就直接接入前端假状态。

## 3. 共享应用壳层实施

### 3.1 目标结构

```text
App
└── AppShell
    ├── Sidebar
    │   ├── LocalSpace 品牌
    │   ├── 资料库 / 合集 / 导入 / 任务导航
    │   └── 设置 / 使用说明 / 侧栏收起
    ├── Topbar
    │   ├── 当前路由上下文
    │   ├── TaskStatusIndicator
    │   ├── NotificationBell
    │   └── 已有的导入 / 设置入口
    └── PageContent
```

建议新增共享 `AppShell`，逐步替代各页面直接使用 `AppHeader` 的方式；现有 API 和 store 不在这一步重写。页面只负责内容，壳层负责导航、任务状态、通知、主题和侧栏布局。

### 3.2 侧栏

- 默认展开，保持当前页面结构可见。
- “收起侧栏”放在左下角设置区域单独一行，不挤占 LocalSpace 品牌行。
- 收起后只保留图标，必须提供可见的展开入口和 `aria-label`。
- 第一阶段只做当前会话状态；如果需要跨重启记住收起状态，另行定义配置键，不直接假设已有接口。
- 不展示本地资料库健康状态，除非先定义真实数据来源。

### 3.3 顶栏

- 删除用户头像。
- 通知使用铃铛图标，复用现有 `NotificationBell` 和通知事件模型。
- 任务进行中使用现有 `TaskStatusIndicator`，展示数量和状态入口，不自行维护一套假任务状态。
- 导入和设置仍使用已有路由入口。
- 应用关闭触发真实退出保护；原型中的关闭按钮只是验证入口，正式产品以 Wails 原生关闭事件为准。

### 3.4 视觉语言

继续采用“Quiet Archive / 静谧资料工作台”作为设计方向：

- 雾面浅灰蓝画布、半透明白色内容层、深墨蓝文字。
- 电光蓝只用于当前状态、主要动作和键盘焦点。
- 纸面卡片只承载真实内容，不把每个区域都包装成浮层。
- 通过缩略图、文件类型色片、任务状态和边线建立层级，不依赖装饰性渐变。
- 工作型页面采用紧凑页头；使用说明作为内容型页面保留较大标题。

## 4. 各页面实施顺序

### 4.1 文件资料库

依赖：`filesStore`、`SearchBar`、`FileTypeFilter`、`CollectionFilter`、`ListDisplayModeToggle`、`PaginationControls`、文件卡片数据。

实施：

1. 先保留现有路由查询参数和分页行为。
2. 将类型、合集、搜索、视图切换压缩成一条工具带。
3. 默认不展开筛选条件；点击筛选后显示小型浮层。
4. 搜索仍调用 `SearchFiles`，不新增全局搜索语义。
5. 文件卡片优先使用真实 `thumbnail`；没有缩略图时使用真实文件类型占位，不使用虚构图片。
6. 保留空资料库、无搜索结果、加载失败和批量选择状态。

验收：刷新、筛选、搜索、分页、分组和路由返回后，状态与当前逻辑一致。

### 4.2 合集

依赖：文件加载、合集接口、文件类型计数和现有 `CollectionCard`。

实施：

- 保留类型筛选和合集搜索。
- 合集卡片只展示真实数量、类型分布和最近修改时间。
- 没有合集时使用现有空状态，不显示预置示例合集。
- 从合集进入文件页时继续使用现有 collection id / 路由逻辑。

### 4.3 导入

依赖：单文件导入、批量导入任务、文件元数据、AI 配置和任务事件。

实施：

- 单文件和批量模式保留现有行为，不把导入页改成静态上传展示。
- 文件选择后才展开元数据表单。
- 批量导入必须明确“创建后台任务”，并能从任务入口继续查看状态。
- AI 标签和描述只在 AI 配置真实开启、接口返回成功时展示建议。
- 导入失败、任务创建失败和重试状态必须沿用真实错误来源。

### 4.4 任务

依赖：`jobsStore`、`GetActiveJobs`、`ListJobs`、任务事件、分页和任务保留配置。

实施：

- 采用紧凑页头，首屏优先展示队列和状态。
- 当前任务和历史任务使用列表，不重复制造大卡片仪表盘。
- 每条任务展示真实标题、时间、进度、状态和可用操作。
- `running / pending / recovering / awaiting_resume / failed` 等状态必须使用现有状态模型。
- 任务状态入口和任务页使用同一份 store 数据，不能分别维护计数。

### 4.5 设置

依赖：现有 SettingsView 子组件和各自 API。

实施：

- 采用紧凑页头，设置导航与右侧内容顶部对齐。
- 左侧设置导航可收起，但不能与全局侧栏混成两个无法区分的层级。
- 先落地已有接口对应的设置项。
- 未接线的启动恢复、自动缩略图策略、布局持久化和分页持久化只记录在设计 backlog，不进入正式 UI。
- 每个设置项必须有加载中、保存中、保存成功和失败反馈。

### 4.6 使用说明

依赖：当前前端静态内容和截图资源。

实施：

- 允许保留较大标题和内容导语，因为页面任务是阅读与理解。
- 目录滚动高亮与页面内容保持当前逻辑。
- 说明文字必须与实际功能一致，不提前承诺未实现能力。

### 4.7 退出保护

依赖：`exitGuardStore`、`GetExitGuardSnapshot`、`ConfirmQuit`、Wails `exit:guard` 事件。

实施：

- 继续使用全局弹层，不把退出保护限制在任务页内。
- 首屏明确说明任务会受到什么影响。
- 展示受保护任务数量、状态、进度和 `canResume`。
- 保留“返回应用、查看任务、仍然退出”三个动作。
- 点击遮罩、按 Esc 和关闭按钮只取消本次退出确认，不修改任务状态。
- 只有真实调用 `ConfirmQuit` 成功后才允许窗口关闭。

## 5. 接口与数据依赖清单

### 第一阶段：只使用已有事实

- 文件：`GetFiles`、`SearchFiles`、合集计数和文件详情。
- 合集：合集列表与文件聚合数据。
- 导入：系统文件选择、单文件导入、批量导入任务。
- 任务：`GetActiveJobs`、`ListJobs`、任务事件。
- 设置：主题、存储目录、存储规则、打开方式、AI、任务保留。
- 退出：`GetExitGuardSnapshot`、`ConfirmQuit`。
- 通知：现有 `NotificationBell` 和通知事件。

### 第二阶段：若确实需要，再新增产品能力

每一项新增偏好都必须先写清楚以下契约：

| 能力 | 需要明确的内容 |
|---|---|
| 启动恢复 | 恢复哪些路由参数、何时保存、初始化失败如何回退 |
| 自动缩略图 | 支持哪些类型、导入时生成还是后台生成、失败如何重试 |
| 默认布局 | 平铺 / 分组的默认值、按用户还是按设备保存 |
| 每页数量 | 允许值、默认值、是否影响历史路由 |
| 侧栏展开状态 | 保存到配置还是仅当前会话 |
| 资料库状态 | 状态来源、刷新时机、异常定义、空目录和未初始化的区别 |

在契约确定前，设计稿只能以“未来能力说明”出现，不能出现可操作开关。

## 6. 实施批次与依赖顺序

### 批次 A：事实冻结与共享状态

- 记录页面、接口、状态、错误和空状态。
- 清理原型中的头像、虚构本地健康状态和未定义全局搜索。
- 确认任务状态、通知和退出保护使用同一套 store / 事件来源。

### 批次 B：共享壳层

- 建立 AppShell、侧栏、顶栏和内容槽位。
- 接入真实任务状态、通知、导入、设置和退出保护。
- 完成侧栏展开 / 收起、响应式和键盘焦点。

### 批次 C：页面视觉落地

- 按文件、合集、导入、任务、设置、说明的顺序逐页改造。
- 工作页统一紧凑页头，文件页优先验证筛选区高度。
- 所有卡片、状态、按钮和空状态使用真实数据与真实动作。

### 批次 D：接口补充（可选）

- 只针对确认过的新增偏好补充数据库配置和 Wails API。
- 先补测试和迁移，再补设置 UI。
- 不为了匹配原型而新增没有实际产品价值的接口。

### 批次 E：联调与验收

- 使用真实空库、未初始化目录、无任务、任务运行中、任务失败、任务可恢复等场景验收。
- 检查设计稿中的每一个状态是否都能从真实数据产生。
- 检查退出、刷新、返回路由、窗口尺寸变化和主题切换。

## 7. 验收标准

### 产品事实

- 页面不出现当前产品不存在的登录、用户身份或本地健康状态。
- 搜索范围、任务数量、通知数量和文件统计均来自真实数据。
- 设置项没有“看起来能改但实际没有接口”的假开关。

### 交互逻辑

- 文件筛选不会改变现有分页、路由和搜索语义。
- 任务页、顶栏任务状态和退出保护显示同一份任务状态。
- 退出保护只保护真实受保护任务，确认退出行为与 `ConfirmQuit` 一致。
- 侧栏收起不影响路由、任务和设置操作。

### 视觉表现

- 工作页首屏优先展示内容，不被大标题和筛选区占据。
- 设置内导航与内容顶部对齐，滚动行为稳定。
- 通知使用铃铛，任务使用进行中状态图标，图标语义不依赖装饰性字符。
- 内容型说明页与工作型页面有明确层级差异。

## 8. 原型使用方式

原型文件位于：[design-prototype/index.html](../design-prototype/index.html)。

原型只用于：

- 比较共享壳层、页面间距和筛选方式。
- 检查任务状态入口和退出保护流程。
- 验证紧凑页头、侧栏收起和设置接口边界的视觉方向。

原型不用于：

- 证明接口已经存在。
- 代替真实数据联调。
- 代替空状态、错误状态和初始化状态设计。
- 作为正式产品的最终交互实现。

## 9. 本方案的执行边界

本方案只定义实施顺序和设计约束，不在本次直接修改现有产品页面。正式开发时，每个批次完成后都需要保留可运行版本，并以产品事实、接口返回和实际用户路径作为最终判断标准。
